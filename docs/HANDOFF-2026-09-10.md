## 5. 踩坑备忘（本会话结论）

- **WIP 死锁三件套**：终态任务不占额度 / cancel 必须收敛子任务 / boot 必须清孤儿——三者缺一不可，
  测试「终态任务孤儿会话」就是为防复发而写。
- **权限门的最终口径**：`executionMode='auto'` → 免确认（创建即 `permissionConfirmed=true`）；
  `'approval'` 且权限高于会话默认 → 须确认。旧任务无 executionMode 按
  `permission === default ? 'approval' : 'auto'` 推导（可追溯 `resolveExecutionMode`）。
- **迭代上限**：默认 null（不限）；上限只是显式防失控开关，达限 T7′ 仍然 blocked 等人（此时才显示提上限按钮）。
- **客户端快照缓存**：`createHttpTransport` 内部维护 `cache` + `inflight` 单飞行；
  `getCachedState()` 供首屏秒画；通知栏与看板共用同一传输实例（`getTransport()` 单例）。
- 宿主重启用 `scripts/restart-host.sh`（nohup 脱离进程组，自动自检路由；curl 只能拿到 401/非 404 判定）。
- 真机事故的 ledger 副本复现路径已删（/tmp/tf-repro），如需再验可从备份文件重建同态场景。

## 7. 补记（2026-09-11 凌晨）：验收语义升级（两期连做）

用户复核任务2 时指出结构性问题：验收对象不该是 AI 自己拆的子任务，而应是任务合同本身；
既没有总任务验收证据，打回还要人选子任务，语义错位。方案确认后两期连做完成：

- **任务级终检（§4.5 升级）**：全部子任务证据齐备后、T5 前，宿主自动跑终检会话
  （JSON 会话形制同拆解，`SessionAdapter.runFinalCheckSession`，模型走拆解槽），
  产物落 `task.evidence`；失败重试 1 次（`finalizeRetries`）再失败兜底直进 review，
  人工可 `generateTaskEvidence` 补跑。T5 从「子任务证据齐」延后为「终检完成（或兜底）」。
- **验收工作台重排（客户端）**：任务级判定面（终检证据卡 + 任务级验收标准逐条对照）优先；
  子任务降级为「执行过程举证（n）」折叠手风琴（标注无需逐个验收）；批准文案改
  「✓ 验收通过（→ done）」；`EvidenceView` 抽象为任务级/子任务级共用。
- **打回定位（§4.6 升级）**：默认路径人只给批语 → `runTriageSession` 把批语映射到
  `{reworkSubtaskIds, note}`，未点名不重跑；失败/无效回退全量；显式 `subtaskIds` 保留为
  API 路径。打回时任务级证据作废（`invalidateTaskEvidence`），终检在重新齐备后重跑。
- **顺带修了一个被新时序暴露的既有并发竞态**：子任务提交证据后状态转 review，但会话
  本体仍在收尾，旧 WIP 计数只看 `in-progress` 状态 → 新任务子任务提前发车破坏「全局串行」。
